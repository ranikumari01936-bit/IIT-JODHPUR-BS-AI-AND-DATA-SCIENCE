1. What is a race condition?                                                                                            A race condition occurs when multiple processes access shared data concurrently, and the final result                depends on the unpredictable timing of their execution.                                                                                                                                                                                2. Why can the final counter value become incorrect?                                                                    Both P1 and P2 read the same stale value (e.g., both read 0), increment it to 1, and write back 1. The               second write overwrites the first, losing one increment. This happens at every step, so 10 increments only           produce 5.                                                                                                                                                                                                                             3. What is the shared resource in this experiment?                                                                      The file /tmp/counter.txt — the shared counter that both processes read and write.                                                                                                                                                     4. How can a mutex lock prevent this problem?                                                                           A mutex (mutual exclusion lock) ensures only one process can execute the critical section (read-modify-              write) at a time. P1 locks → reads → increments → writes → unlocks; only then can P2 proceed. This                   serializes access, guaranteeing all 10 increments are counted.
